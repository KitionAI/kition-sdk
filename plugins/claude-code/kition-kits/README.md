# kition-kits: the Kition kits in Claude Code

A Claude Code plugin that lets Claude create, inspect, edit and check files in your project with
published Kition kits through their Kit Harness Protocol (KHP) tools. The published kits are
Note, for Markdown documents; Table, for `.ktable` tables; and HTML, for `.html` pages. No Kition app needs to run: the
plugin starts kition-sdk's `kition-kits-mcp`, which drives each kit's headless executable on the
files in your project folder.

What it adds:

- **An MCP server, `kition-kits`**: the KHP tools (`kit_inspect`, `kit_commands`, `kit_run`,
  `kit_check`, `kit_query`, `kit_batch`, `kit_export`, `kit_create`, `kit_draft_ready`,
  `kit_draft_reopen`), routed to the right kit by the file's extension. The workspace is the
  project folder (`${CLAUDE_PROJECT_DIR}`); paths outside it are refused (KHP A29).
- **A skill per published kit, `<kit>-editing`**: the kit's own model guide (`agent/guide.md` in its
  repository): how its documents are built, how objects are addressed, the workflow (inspect,
  find commands, run in small steps, check, fix) and two worked examples. Claude loads one when
  you work with that kit's files.
- **Draft review, the person's side**: `/kition-kits:drafts-list` and `/kition-kits:drafts-compare
  <file>` show what an agent drafted (`draft: true`); `/kition-kits:drafts-merge <file>` and
  `/kition-kits:drafts-discard <file>` keep or drop it. Merge and discard can only be started by
  you, never by Claude on its own (KHP A14).

## Install

From a kition-sdk checkout:

```sh
claude plugin marketplace add ./plugins/claude-code
claude plugin install kition-kits@kition
```

The plugin needs the server. It uses, in this order: the plugin's `kition-kits-mcp` option;
`kition` on the `PATH`, started as `kition mcp`; `kition-kits-mcp` on the `PATH`; otherwise
`npx -y @kition/kits-mcp`, the npm package that brings `kition` for your platform (Node.js
needed). `kition` holds no kit: it downloads each published kit into `~/.kition/kits` the first
time Claude opens a file of it (kition-sdk's `docs/sdk/cli.md`). Without Node.js,
install `kition` and put `~/.kition/bin` on the `PATH`:

```sh
curl -fsSL https://github.com/KitionAI/kition-sdk/releases/latest/download/install.sh | sh
```

or build it:

```sh
cargo build -p kition-cli   # then set the option to target/debug/kition
```

Claude Code then asks for the plugin's options (change them later with `/plugin` or `/config`):

| Option | What it is |
| --- | --- |
| `kition-kits-mcp` | The server executable: `kition` (such as `target/debug/kition` from the build above) or a `kition-kits-mcp`. Empty: `kition` on the `PATH`, else `kition-kits-mcp` on the `PATH`, else `npx -y @kition/kits-mcp` |
| Installed kits | A folder with one folder per kit, each holding its `kit.json` and headless executable. Empty: the kits `kition` installs in `~/.kition/kits` |
| Kit repositories (development) | A folder of kit checkouts, `kition-<kit>/`. Every kit built there with `cargo build -p kition-<kit>` is served from `target/debug/kition-<kit>` with its repository's `kit.json`. With the kits checked out next to kition-sdk, this is kition-sdk's parent folder |
| One tool set for all kits | On (the default): `kit_<action>` tools routed by file extension. Off: `<prefix>_<action>` tools per installed kit, such as `note_run` and `note_check` |

Restart Claude Code, or run `/reload-plugins`, after changing an option. `/mcp` shows whether the
server started; if it didn't, its message names the missing executable.

## How it fits together

- `.claude-plugin/plugin.json` declares the server and the options. The server is started through
  `scripts/kits-mcp.sh`, which turns the options into the server's arguments (`--kits-dir`,
  one `--kit` per built kit repository, `--unified`), picks the server (above), and starts
  `kition` as `kition mcp`.
- `skills/<kit>-editing/SKILL.md` is generated by `node tools/claude-plugin-skills.mjs` (in
  kition-sdk) from each published kit's `agent/guide.md` and `kit.json`. The publication
  allowlist is `published-kits.json` at the SDK root. Edit the guide in the kit's
  repository, never the skill; `node tools/claude-plugin-skills.mjs --check` fails when they
  differ.
- `node tools/claude-plugin-probe.mjs -- <command>` starts a server the way Claude Code does and
  prints what it offers (tools and the size of their definitions).

## Limits

- The launcher is a POSIX shell script: macOS and Linux. On Windows, configure the server yourself
  in `.mcp.json` with `npx -y @kition/kits-mcp --workspace <folder> --unified`, or
  `kition mcp --workspace <folder> --unified` (`kition` from `install.ps1`, docs/sdk/cli.md).
- The server is free on any machine and needs no licence key.
- One server serves every kit, so its MCP `serverInfo.version` is the server's own; each kit's
  version is in its manifest resource, `khp://kits/<id>/kit.json` (KHP K20).
